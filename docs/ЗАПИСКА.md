# Пояснительная записка

**Проект:** распознавание нестандартных государственных регистрационных знаков (ГРЗ) РФ
типов 1, 1А, 1Б с отсевом типа `other`.
**Формат выхода:** `image;plate_num;plate_type;confidence` (UTF-8, разделитель `;`).
**Режим:** полностью офлайн, без обращений к внешним сервисам.

---

## 1. Задача и ограничения

На вход подаётся каталог изображений с камер у шлагбаумов, парковок, регистраторов и
съёмки с рук: перспективные искажения, ночь, дождь, грязь, блики, мелкие знаки. Требуется
для каждого изображения вернуть номер в формате `A123BC456` / `A123BC45`, тип знака
(`type1`, `type1a`, `type1b`, `other`) и уверенность; нечитаемые позиции обозначаются `#`.

Ключевые ограничения задания, которые определили архитектуру:

- офлайн-инференс, без API и сети;
- ≤ 100 мс на изображение на референсной конфигурации (Intel i5-7600, GTX 1050 Ti 4 ГБ, 16 ГБ RAM);
- модели и веса передаются вместе с решением;
- запрещены хардкод ответов, обращение к внешним сервисам и выдача автоматической разметки за ручную;
- датасет публикуется под CC BY 4.0;
- собственная съёмка реальных номеров недоступна.

## 2. Данные

### 2.1. Реальные изображения

Реальные кадры собраны только из разрешённых источников — Wikimedia Commons
(CC0, Public domain, CC BY). Каждый кадр прошёл **ручную** разметку в локальном
инструменте `dataset/annotate_images.py`: рамка знака, номер, тип, признак «на ТС».
Журнал разметки — `dataset/real_review_inbox/review.csv`.

| Показатель | Значение |
|---|---|
| Размеченных знаков | 184 |
| Кадров с разметкой | 164 |
| `type1` | 147 |
| `type1b` | 32 |
| `type1a` | 5 |
| Негативов (целевого знака нет) | 10 |

Разметка ручная: координаты рамки и строка номера вводились человеком, автоматическая
разметка за ручную не выдаётся. Изображения в репозиторий не включены — только журнал
с URL, лицензией и атрибуцией; условия конкретных файлов требуют проверки перед
публикацией набора под CC BY 4.0.

### 2.2. Синтетические данные

Синтетика генерируется собственным воспроизводимым генератором
(`dataset/generator/`, фиксированный `--seed`) и не нарушает ограничений задания:

- рендер пластины по ГОСТ Р 50577-2018: 520×112 мм (типы 1, 1Б) и 290×170 мм (тип 1А);
- алфавит `ABEKMHOPCTYX`, маска `[Б][Ц][Ц][Ц][Б][Б][код 2–3 цифры]`, коды регионов;
- вставка знака в сцену с перспективным искажением, подгонкой яркости под сцену,
  блюром, шумом, дождём/снегом, грязью, бликами, ночью;
- точная разметка `bbox` и `quad` (4 угла по часовой стрелке от левого верхнего);
- класс `other` — знаки вне области задания (для отсева).

Сгенерировано 6000 кадров, 6630 знаков: 1789 `type1`, 1994 `type1a`, 1513 `type1b`,
1334 `other`. Метаданные — `meta.csv` (поля `image;plate_num;plate_type;bbox;quad;…;
license;conditions`).

## 3. Архитектура решения

Пайплайн из трёх шагов; модели маленькие и при необходимости экспортируются в ONNX:

1. **Детектор** — YOLOv8n (3.01 млн параметров, 8.2 GFLOPs при 640×640). Один проход даёт
   рамку знака и его тип (4 класса). Выбран как самый быстрый вариант из семейства
   YOLOv8/v5/RT-DETR: одностадийная anchor-free схема при 640 px укладывается в бюджет
   времени заметно лучше двухстадийных детекторов при сопоставимом качестве на мелких знаках.
2. **OCR** — компактная CRNN + CTC: 4 свёрточных блока (32→64→128→192 канала),
   `AdaptiveAvgPool2d((1, None))`, 2-слойная двунаправленная LSTM (128), линейный
   классификатор на 33 класса (32 символа + blank). Вход — grayscale 64 px по высоте,
   ширина ≤ 384. CTC выбран вместо tesseract, потому что:
   - tesseract не является обучаемым под конкретный шрифт ГОСТ и не даёт уверенности по символам;
   - CTC не требует посимвольной сегментации, устойчив к слипанию символов и перспективе;
   - модель весит ~4 МБ и работает за единицы миллисекунд на GPU.
3. **Постобработка** — детерминированная, без «угадывания»:
   - тип берётся из детектора (на ручной разметке он верен в 99.4 % найденных знаков);
     доля жёлтых пикселей HSV может исправить только белый тип на 1Б, но не наоборот,
     чтобы тусклый жёлтый знак не превращался в белый;
   - OCR прогоняется на нескольких кропах (разные отступы и нормализация аспекта) и, для
     белых знаков, по обеим раскладкам (одно-/двухстрочной); выбирается самый читаемый
     результат;
   - недопустимые для позиции символы заменяются на `#`, короткий хвост добивается `#`;
     длина 8/9 (тип 1, 1А) и 7/8 (тип 1Б) сохраняется, так как код региона бывает двух- и
     трёхзначным;
   - на изображение выдаётся ровно одна строка — лучшая целевая детекция; при её отсутствии
     `other` с пустым номером.

## 4. Обучение

**Детектор.** Сначала 40 эпох на синтетике (mAP50 0.974 на синтетической валидации).
Затем fine-tune 14 эпох на смеси: 5.1 тыс. синтетических кадров + 131 реальный кадр
(повторён 4 раза, чтобы доля реального домена была заметной) + 10 реальных негативов.
Аугментации Ultralytics: mosaic, случайные масштаб/сдвиг/поворот, HSV; горизонтальное
отражение отключено, чтобы не портить геометрию знака.

**OCR.** 14 эпох на смеси из трёх источников: реальные ручные кропы (45 % выборки),
кропы знаков из синтетических сцен, полученные пересчётом `quad` в прямоугольник
(35 %), и чистые рендеры ГОСТ (20 %), затем ещё 8 эпох дообучения с уменьшенным шагом
(итоговый чекпойнт `ocr_v3.pt`). Аугментации: перспектива, поворот ±5°, изменение
разрешения, яркость/контраст/насыщенность, гауссов и медианный блюр, шум, неравномерная
засветка, JPEG-артефакты. Loss — CTC, оптимизатор AdamW, cosine-расписание.

## 5. Результаты

Все замеры — на собственной ручной разметке реальных кадров (164 кадра, 184 знака).
Независимого теста организаторов нет, поэтому цифры ниже — оценка снизу/сверху, а не
соревновательный результат.

| Метрика | Значение |
|---|---|
| Детекция знака, IoU ≥ 0.5 | 172/184 = **93.5 %** |
| Верный тип среди найденных | 171/172 = **99.4 %** |
| OCR по эталонному кропу, точное совпадение | 67/184 = **36.4 %** |
| OCR по эталонному кропу, совпавших символов | 877/1497 = **58.6 %** |
| OCR на 40 отложенных кадрах (не в обучении) | **22.5 %** точных, **47.9 %** символов |
| Сквозное совпадение номера и типа (production-пайплайн) | 51/164 = **31.1 %** |

Для сравнения: исходная модель, обученная только на чистых синтетических рендерах,
давала на тех же кадрах детекцию 15.2 % и **ноль** точных номеров (все позиции `#`).
Дообучение на реальных кропах и сценах подняло детекцию до 93.5 %, а сквозное
распознавание — с 0 до 31.1 %.

Ограничения интерпретации:

- 137 из 184 кропов участвовали в обучении OCR, поэтому 36.4 % оптимистичны; 22.5 % на
  40 отложенных кадрах — более честная оценка.
- Сквозная метрика ниже OCR-метрики: рамка детектора теснее ручной, масштаб символов
  отличается. В пайплайне это компенсируется подбором отступов и нормализацией аспекта
  кропа (прирост сквозной метрики с 17.1 % до 31.1 %).
- Тип 1А представлен 5 аннотациями, тип 1Б — 32; по ним статистика недостоверна.

## 6. Скорость

Замер на локальной RTX 4060 (8 ГБ), после прогрева, 498 изображений подряд, без
параллельных задач:

| Показатель | Значение |
|---|---|
| Полный пайплайн (детектор + OCR-подбор кропов) | 38.6 с на 498 кадров = **77.5 мс/кадр** |
| Детектор отдельно (YOLOv8n, 640 px) | ~15 мс/кадр |
| OCR (CRNN, 64 px, до 10 прогонов на кадр) | остальное время |

Требование ≤ 100 мс относится к референсной конфигурации i5-7600 + GTX 1050 Ti.
GTX 1050 Ti примерно в 2–2.5 раза медленнее RTX 4060 по FP32, поэтому **на референсной
машине лимит, скорее всего, не выполняется**; замер там не проводился и в записке не
заявляется. Для ускорения предусмотрены: уменьшение числа кропов-кандидатов OCR,
экспорт в ONNX/TensorRT и уменьшение `imgsz` детектора.

## 7. Ограничения

- Мало реальных данных: 184 аннотации, 5 из них типа 1А. Для устойчивого качества нужны
  сотни кадров на каждый тип, включая ночь и сильный блюр.
- Сквозная точность 31.1 % — это MVP. Основные ошибки: похожие символы (`O/0`, `B/8`,
  `H/M`, `C/E`), смазанный код региона, ночные кадры и грязь.
- Референсная конфигурация (GTX 1050 Ti, i5-7600) не проверялась; требование ≤ 100 мс
  на ней не подтверждено. Замер выполнен на RTX 4060.
- Лицензии реальных изображений смешанные (CC0 / Public domain / CC BY). Публикация
  всего набора под CC BY 4.0 требует построчной проверки; сейчас в репозитории только
  журнал разметки, без изображений.
- Веса детектора получены из Ultralytics YOLOv8n (AGPL-3.0) — перед распространением
  нужно проверить совместимость с условиями олимпиады.

## 8. Идеи развития

- больше реальных кадров типов 1А/1Б (сейчас 5 и 32 аннотации — статистически мало);
- выпрямление знака по `quad` на инференсе (сейчас используется только `bbox`+поворот);
- экспорт в TensorRT/ONNX и замер на референсной GTX 1050 Ti;
- ансамбль из двух разрешений OCR и TTA по контрасту;
- полноценный классификатор типа вместо эвристик по геометрии/цвету.

## 9. Запуск

```powershell
python -m pip install -r solution/requirements.txt
python solution\predict.py --input path\to\images ^
    --weights solution\weights\best_v2.pt ^
    --ocr-weights solution\weights\ocr_v3.pt ^
    --output predictions.csv --device 0
```

Без `--ocr-weights` решение работает как детектор типов и честно пишет `#` во всех
позициях номера.
