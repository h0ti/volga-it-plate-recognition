# Датасет и сбор открытых изображений

## Текущее состояние набора

| Часть | Где лежит | В репозитории |
|---|---|---|
| Ручная разметка реальных кадров (184 знака, 164 кадра) | `real_review_inbox/review.csv` | да, только журнал |
| Реальные изображения (Wikimedia Commons, CC0/PD/CC BY) | `../data/commons/images/` локально | нет, лицензии смешанные |
| Синтетика по ГОСТ (6000 кадров, 6630 знаков) | `generated_4060/` локально | нет, генерируется скриптом |
| Генератор синтетики | `generator/` | да |

Синтетический набор воспроизводится командой
`python dataset\generator\build_dataset.py --count 6000 --out dataset\generated_4060`
при фиксированном `--seed`. Метаданные включают `image;plate_num;plate_type;bbox;quad;
is_vehicle;is_synthetic;source;license;conditions`.

Реальные изображения в репозиторий не включены: у файлов разные лицензии
(CC0, Public domain, CC BY), и публикация всего набора под CC BY 4.0 требует
построчной проверки. Журнал разметки хранит URL, лицензию и атрибуцию каждого кадра.

## Сбор открытых изображений

Скрипт `collect_open_datasets.py` собирает только источники, явно перечисленные
в JSON-конфигурации. Сейчас в `sources.json` записан один кандидат с Wikimedia
Commons: CC0-фотография автомобиля с обычным российским номером. Страница файла
указывает CC0; изображение скачано в `images/real/commons-russian-plate-cc0/`.
Это один пример, а не готовый датасет: тип в `collection.csv` остаётся
`unknown`, ручная проверка и отдельная разметка всё ещё нужны. Источник не
содержит подтверждения наличия редких типов 1А/1Б.

## Установка и конфигурация

Используйте Python 3.10+ и установите зависимости:

```powershell
python -m pip install -r dataset/requirements.txt
```

Скопируйте `dataset/sources.example.json` в `dataset/sources.json` и добавьте
проверенные источники. Файл `sources.json` локальный, в репозиторий его
добавлять не нужно. Поля общего назначения:

| Поле | Назначение |
| --- | --- |
| `name` | Уникальный slug источника из латинских букв, цифр, `_` и `-`. |
| `provider` | `requests`, `kaggle` или `roboflow`. |
| `source_url` | HTTPS-страница набора/источника для фиксации происхождения. |
| `license` | Точное название лицензии; если неизвестна — `ПРОВЕРИТЬ ЛИЦЕНЗИЮ`. |
| `license_verified` | `true` только после ручной проверки условий использования и атрибуции. |
| `attribution` | Автор/текст атрибуции, если этого требует лицензия. |
| `images_are_plate_crops` | `true`, только если файлы источника — кропы самих ГРЗ. |

Для `requests` укажите массив `urls` с прямыми ссылками на изображения.
Для Kaggle дополнительно укажите `dataset` (`owner/dataset`); для Roboflow —
`workspace`, `project`, числовой `version` и `format` экспорта. Идентификатор
площадки или набора сам по себе не является лицензией: не ставьте
`license_verified: true`, пока не проверили лицензию конкретных изображений и
разрешение на их использование/публикацию.

Пример структуры источников (не содержит одобренных наборов или ссылок):

```json
{
  "sources": [
    {
      "name": "my-verified-source",
      "provider": "requests",
      "source_url": "https://example.org/dataset-page",
      "license": "УКАЖИТЕ ПРОВЕРЕННУЮ ЛИЦЕНЗИЮ",
      "license_verified": false,
      "attribution": "",
      "images_are_plate_crops": false,
      "urls": []
    }
  ]
}
```

Замените все значения-заполнители реальными сведениями; ссылка-пример не
является источником. Непроверенные лицензии по умолчанию пропускаются. Флаг
`--include-unverified` скачивает их только в `dataset/quarantine/unverified/`;
эти файлы нельзя считать одобренными, использовать для обучения или
распространять до проверки.

## Ключи API

Передавайте ключи через переменные окружения текущего процесса — скрипт не
записывает их в конфигурацию:

```powershell
$env:KAGGLE_USERNAME = "ваш_username"
$env:KAGGLE_KEY = "ваш_api_key"
$env:ROBOFLOW_API_KEY = "ваш_api_key"
```

Получайте ключи только через официальные настройки соответствующей площадки.
Не вставляйте ключи в JSON, исходный код или публикуемые команды.

## Запуск и результаты

```powershell
python dataset/collect_open_datasets.py --config dataset/sources.json
python dataset/collect_open_datasets.py --config dataset/sources.json --filter-type type1a
python dataset/collect_open_datasets.py --help
```

Проверенные источники сохраняются в `dataset/images/real/<source>/`.
`dataset/collection.csv` хранит путь, источник, исходную страницу, лицензию,
атрибуцию и статус. Непроверенные источники помещаются в карантин с явным
статусом. Скрипт не меняет `dataset/meta.csv`: этот файл предназначен для
проверенной разметки, а `collection.csv` — журнал загрузок и кандидатов.

Фильтры типа работают **только** если `images_are_plate_crops: true`.
type1a предлагается по диапазону aspect ratio, type1b — по доле жёлтых пикселей
в HSV, type1 — по вытянутому aspect ratio. Это простые эвристики, не
распознавание ГОСТ и не ручная проверка. Для обычных фотографий машин оставьте
`images_are_plate_crops: false`: тип будет `unknown`, исходный кадр не будет
ошибочно классифицирован по габаритам всего изображения.

Перед сбором соблюдайте условия сайта и лицензии, включая ограничения на
массовое скачивание и атрибуцию. Kaggle/Roboflow могут загружать архив целиком;
`--max-images` ограничивает копирование обработанных изображений, но не размер
архива, загружаемого адаптером. Скрипт принимает только явные URL/идентификаторы,
не выполняет поиск источников, не обращается к запрещённым площадкам и не
включает скрытые/организаторские наборы.

Основа генератора синтетики и безопасный тестовый запуск описаны в
[`generator/README.md`](generator/README.md). Генератор работает отдельно и не
перезаписывает этот файл `meta.csv`.

Для удобной ручной разметки локальных изображений есть оконное приложение:
запустите [`start_annotation.bat`](start_annotation.bat). Инструкция, горячие
клавиши и маски типов находятся в
[`real_review_inbox/README.md`](real_review_inbox/README.md); приложение
сохраняет разметку отдельно и не добавляет её автоматически в `meta.csv`.
